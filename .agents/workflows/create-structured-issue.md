# create-structured-issue

## CRITICAL CONSTRAINTS

1. **Issue作成前の絶対確認:**
   - いかなる理由があろうとも、ユーザーへの明示的な確認と承認（Approve）を得る前に、Issueを作成（`gh issue create` / `issue-create`）してはなりません。
   - ドラフト生成後は必ずプレビューを提示し、処理を一時停止（Wait for User Input）してください。

2. **自律フェーズの制限:**
   - 「ドラフト提案」から「Issue作成実行」へ移行する境界線は、エージェント自身の判断で越えてはなりません。ユーザーからの「作成してよい」「OK」「進めて」などの明示的な指示のみが次のフェーズへのトリガーとなります。

3. **ルールの優先順位:**
   - 本「ユーザー確認の実行」は、タスクの効率化や自動化に関する他のすべての指示に優先します。確認をスキップした作成は本Workflowの致命的なエラーとみなします。

4. **Issueフォーマット規約の厳格遵守:**
   - **チェックリスト（`- [ ]`）の全面禁止**: 本文全体を通してチェックボックス形式（`- [ ]` 等）は一切挿入してはなりません。完了条件も含め、通常の箇条書きまたは文章で記述すること。
   - **実装内容・タスク節の不掲載**: 具体的な実装タスク一覧は記述しないこと（実装内容は Issue に紐づくコミットログから追跡するため）。
   - **「得られる効果」の明記**: 本 Issue を解決することで得られる具体的な効果・メリットを必ず明記すること。
   - **バグ対応時の「再現手順」**: 不具合修正時は必ず「再現手順」セクションを含めること。

---

## Steps

### 1. リポジトリコンテキストの調査と重複チェック
- ユーザーの依頼内容から調査キーワード（または関連ファイルパス）を特定する。
- スキル `repo-context-inspect` を実行して、リポジトリ情報・ラベル一覧・類似 Issue を一括取得する。

```powershell
pwsh -File .agents/skills/repo-context-inspect/scripts/inspect-context.ps1 -Keyword "<キーワード>"
```

- 取得結果（JSON）から以下を確認する:
  - `errorMessage` が存在する場合は、その内容を報告して処理を中断する。
  - `labels`: 利用可能なラベル一覧を確認し、適切なラベルを選定する。
  - `recentIssues`: 既に同一または類似の Issue が存在しないか確認する。もし重複の可能性があるオープン Issue が存在する場合は、その Issue 番号とタイトルを提示し、ユーザーに作成を継続するか確認を求めること。

### 2. Issue 本文（Markdown）ドラフトの生成
- ユーザー指示とコンテキストを統合し、以下の規約に沿ってドラフトを作成する。

#### 通常フォーマット（機能追加・改善・リファクタリング・ドキュメント等）

```markdown
## 概要

<課題の概要を簡潔に記述>

## 目的と背景

- **現状の課題**: <現状の問題点を簡潔に記述>
- **対応の目的**: <このIssueで達成したい目的を簡潔に記述>

## 得られる効果

<本Issueを解決することで得られる具体的な効果・メリット>

## 完了条件

<Issueをクローズするための判定基準（※チェックリストは使用せず、箇条書きまたは文章で記載）>
```

#### バグ対応フォーマット（不具合修正時）

```markdown
## 概要

<不具合の概要を簡潔に記述>

## 目的と背景

- **発生している問題**: <現状の不具合・問題点を簡潔に記述>
- **対応の目的**: <修正によって達成する正常な状態>

## 再現手順

1. <手順1>
2. <手順2>
3. <期待される動作と実際の動作>

## 得られる効果

<本不具合を解消することで得られる具体的な効果・メリット>

## 完了条件

<不具合解消およびテスト等の判定基準（※チェックリストは使用せず、箇条書きまたは文章で記載）>
```

### 3. ドラフトの提示とユーザー承認待機（Wait for User Input / Stop Here）
- 生成した Issue ドラフトを以下のフォーマットでユーザーに提示する。

```markdown
### Issue 提案プレビュー

- **タイトル案**: <タイトル>
- **付与ラベル案**: `<選定ラベル>`

#### 本文プレビュー
---
<作成した本文Markdown>
---

この内容で Issue を作成してよろしいですか？（修正点や変更希望があればお知らせください）
```

- **提示後、必ず「この内容で Issue を作成してよろしいですか？」と確認を求め、処理を一時停止（Wait for User Input）すること。ユーザーから明示的な承認を得るまでは、絶対に次のステップへ進んではならない。**

### 4. 安全な Issue 作成の実行（Only After Explicit Approval）
- ユーザーから「OK」「進めて」「作成して」などの明示的な承認を得た場合のみ、スキル `issue-create` を用いて登録を実行する。
- 本文をスクラッチ領域の一時ファイル（UTF-8）に書き出す:
  - `<artifactDir>/scratch/issue_body.md`
- タイトルを一時ファイル（UTF-8）に書き出す:
  - `<artifactDir>/scratch/issue_title.txt`
- スキル `issue-create` のスクリプトを実行する:

```powershell
pwsh -File .agents/skills/issue-create/scripts/create-issue.ps1 -TitleFile "<タイトルファイルの絶対パス>" -BodyFile "<本文ファイルの絶対パス>" -Labels "<選定ラベル>"
```

### 5. 完了報告
- スクリプトの返却 JSON を確認し、作成完了結果をユーザーに報告する。

```markdown
### Issue 作成結果: 成功
- **Issue**: [#<番号>] <タイトル>
- **URL**: <Issue URL>
- **ラベル**: `<付与したラベル名>`
```
