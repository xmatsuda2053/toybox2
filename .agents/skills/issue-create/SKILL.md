# issue-create

GitHub CLI (`gh`) を利用し、特殊文字のエスケープ漏れや複数行本文によるシェル破損を防止しながら、プロジェクト規約に沿った GitHub Issue を安全に作成するスキルです。

---

## 厳格な制約事項（CRITICAL CONSTRAINTS）

1. **チェックリスト（`- [ ]`）の全面禁止**:
   - 本文全体を通して、チェックボックス形式（`- [ ]` 等）は**一切挿入してはならない**。完了条件を含め、通常の箇条書きまたは文章で記述すること。

2. **実装内容・タスク節の不掲載**:
   - 具体的な実装タスク一覧は記述しないこと（実装内容は Issue に紐づくコミットログから追跡するため）。

3. **「得られる効果」の明記**:
   - 本 Issue を解決することで得られる具体的な効果・メリットを必ず明記すること。

4. **バグ対応時の「再現手順」セクション**:
   - 不具合・バグ対応（`bug` ラベル付与時など）の場合は、必ず「再現手順」セクションを含めること。

5. **安全なファイル経由の受け渡し**:
   - 複数行の本文は必ずスクラッチ領域の一時 Markdown ファイル（UTF-8）に保存し、ファイルパスを指定して実行すること。
   - タイトルに記号（`"`, `$`, `[]`, `&` など）が含まれる場合は、タイトルも一時ファイルに保存して `-TitleFile` で渡すことを推奨する。

---

## パラメータ（Parameters）

- `title`: Issue のタイトル文字列（`title_file` を指定しない場合は必須）
- `title_file`: タイトルが記載された一時ファイルのパス（記号混在時に推奨）
- `body_file`: Issue 本文が記載された Markdown ファイルのパス（**必須**）
- `labels`: 付与するラベルの配列またはカンマ区切り文字列（任意。例: `enhancement`, `bug`）
- `repo`: 対象リポジトリ（`owner/repo`。任意。省略時はローカルの Git リモートから自動取得）
- `dry_run`: 登録を行わず引数検証のみ行うスイッチ（任意）

## Issue 本文のフォーマット規約

本文（`body_file`）は以下のいずれかのテンプレートに厳格に従って作成すること。

### 1. 通常フォーマット（機能追加・改善・リファクタリング・ドキュメント等）

```markdown
## 概要
<課題の概要を簡潔に記述>

## 目的と背景
- **現状の課題**: <現状の問題点を簡潔に記述>
- **対応の目的**: <このIssueで達成したい目的を簡潔に記述>

## 得られる効果
<本Issueを解決することで得られる具体的な効果・メリット>

## 完了条件
<Issueをクローズするための判定基準（※チェックリストは使用せず、箇条書きまたは文章で記載）>
```

### 2. バグ対応フォーマット（不具合修正時）

```markdown
## 概要
<不具合の概要を簡潔に記述>

## 目的と背景
- **発生している問題**: <現状の不具合・問題点を簡潔に記述>
- **対応の目的**: <修正によって達成する正常な状態>

## 再現手順
1. <手順1>
2. <手順2>
3. <期待される動作と実際の動作>

## 得られる効果
<本不具合を解消することで得られる具体的な効果・メリット>

## 完了条件
<不具合解消およびテスト等の判定基準（※チェックリストは使用せず、箇条書きまたは文章で記載）>
```

## 実行手順（Workflow Steps）

### 1. 一時ファイルの準備
本文（および必要に応じてタイトル）をスクラッチ領域の一時ファイル（UTF-8）として作成する。
- 本文: `<artifactDir>/scratch/issue_body.md`
- タイトル（記号保護時）: `<artifactDir>/scratch/issue_title.txt`

### 2. Issue 作成スクリプトの実行

#### 基本実行（TitleFile 利用・推奨）:
```powershell
pwsh -File .agents/skills/issue-create/scripts/create-issue.ps1 -TitleFile "<タイトルファイルの絶対パス>" -BodyFile "<本文ファイルの絶対パス>" -Labels "<ラベル1>","<ラベル2>"
```

#### タイトル直接指定（特殊記号を含まない場合）:
```powershell
pwsh -File .agents/skills/issue-create/scripts/create-issue.ps1 -Title "<タイトル文字列>" -BodyFile "<本文ファイルの絶対パス>" -Labels "<ラベル名>"
```

### 3. 実行結果の確認と報告
スクリプトから返却される JSON を解析し、ユーザーへ最終結果を報告する。

#### 成功時の報告フォーマット:
```markdown
### Issue 作成結果: 成功
- **Issue**: [#<番号>] <タイトル>
- **URL**: <Issue URL>
- **ラベル**: `<付与したラベル名>`
```

#### 失敗時の報告フォーマット:
```markdown
### Issue 作成結果: 失敗
- **エラー原因**: <errorMessage の内容>
- **対処方法**: <認証確認や入力内容の確認等の案内>
```
